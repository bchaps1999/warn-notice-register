# Date evidence and timing eligibility

This contract separates a stored date string from evidence that its **role** and **day precision** are correct. It complements the [source-first rebuild contract](rebuild-contract.md) and the [cross-state date audit](date-candidate-audit-2026-09-23.md).

## Three event dates

A notice may have a notice date, an effective/layoff start, and an effective/layoff end. A posting or receipt date is a distinct agency event. A list of separation dates is a set of phases, not automatically an interval. When an agency reports a start/end range, both endpoints must be preserved and checked separately. Null means the source or correspondence has not established the value; it must not be replaced by the other endpoint.

Each canonical scalar date has a nullable `precision` and `basis`. `day`, `month`, `year`, and `unknown` describe the precision of the **source fact**, not the number of digits in an ISO storage string. Null precision means not assessed. `reported` means a reviewed filing or audited source-field rule establishes the date role and matches the selected value. `derived_from_reported_components` means a documented, checked projection from explicit source components. Other inferred bases remain visible but are not eligible for exact-day research. Source field name, raw text, parser/rule version, artifact hash, and decision reference belong in `source_details` or the source ledger.

The existing notice fields are `notice_date_precision` and `notice_date_basis`. The storage rollout added the same two fields for `effective_date` and `effective_date_end`. It does **not** backfill `day` just because a stored date has `YYYY-MM-DD` form. In older candidates, New Jersey's inferred posting-month placeholder is marked `month` and excluded from timing. The latest staged source-first correction removes that placeholder from canonical `notice_date` and keeps the yearless posting month in `source_details`.

## Timing outputs

`python -m warnlive.verify.timing <isolated-candidate.sqlite> --out-dir <new-dir>` is read-only. It keeps the legacy `provisional_day_timing_cohort.csv` for comparison. That output accepts null notice precision provisionally and is not a source-verified research sample.

The new `date_eligibility_by_notice.csv` reports independent evidence status for notice, start, and end, plus combined notice-to-start and notice-to-end eligibility reasons for every candidate notice. `source_supported_start_timing_cohort.csv` requires the notice and start to each have valid canonical ISO days, explicit `day` precision, a source-supported basis, and no unresolved date/range review flag. The end cohort applies the same test to notice and end independently, and holds a known reversed range. A missing end does not block notice-to-start timing. Negative intervals remain visible when the underlying dates are source-supported; they are not silently clamped or discarded.

On the reviewed New York candidate before effective-date precision metadata was added, there are 86,388 notices, 58,265 pairs of stored notice/start strings, and 55,999 provisional day-formatted pairs. The source-supported start and end cohorts are both **empty**. That is an accurate statement about that older candidate's metadata, not proof that no true interval can be measured.

The later isolated candidate with both reviewed New York filings admits 3E Logistics (14 days) and First Transit (101 days) to both strict cohorts. A subsequent source-format rule for Florida's archived HTML tables adds 2,552 supported notice-to-start rows and 1,241 supported notice-to-end rows. Each table is checked for the exact `COMPANY NAME`, `NOTICE DATE`, `LAYOFF DATE`, `EMPLOYEES AFFECTED`, `INDUSTRY` header order; only whole-cell parsed dates receive `day`/`reported`. Ordered `thru` pairs retain both endpoints. Eleven reversed pairs have blank effective endpoints and a review flag. The rule identifier and source field names are saved in `source_details`, the raw cells remain in the version, and the archive bytes are in the source bundle. The latest staged candidate also preserves 63 ordered New Jersey effective ranges and separates `and` pairs into phase lists without a continuous end. New Jersey's legal notice day is absent from the frozen source, so none of its 2,327 observations qualifies for notice-to-effective timing. A separately audited 2026 South Carolina agency report adds 26 supported notice/start pairs and eight supported range ends, with [source limits](sc-2026-date-evidence.md). A [reviewed Sodexo decision](ny-date-reconciliation-2026-09-23.md) adds one nine-day notice-to-reported-closing/action start row. The filing's employee separation dates are distinct phases, including an approximate frontline date, and are carried as separate provenance; the nine days are not an exact notice-to-employee-separation interval. Thus the v5 strict cohorts contain **2,581 start** and **1,251 end** rows, mostly from one Florida source path. Those totals are not nationwide date-quality estimates.

## Rollout and release checks

1. The nullable start/end precision and basis fields now pass through an idempotent schema migration, version snapshots, CSV, and site output. Existing date strings and row identities remain preserved for metadata-only rules.
2. Set `day`/`reported` only for guarded filing decisions and audited source-format rules. Reviewed New York filings, Florida archived HTML, and the pinned South Carolina 2026 report are admitted paths. New Jersey's posting-month role and effective ranges have a separate staged correction, but event identity remains unresolved in some groups. Continue New York historical, Pennsylvania, other South Carolina years, and other state checks. BLN-only fallback dates stay unassessed until linked to source evidence.
3. For every rule, freeze positive and negative source examples. Check that selected date values match the cited source field or component; keep malformed, reversed, phase, posting, and amendment cases separate.
4. Report eligibility and exclusion reasons by state **and source format**, with worker-weighted and negative-interval summaries. Verify that metadata-only changes do not alter notice counts, worker totals, IDs, or links. Repeat fixed-input replay and export/site comparisons before using the strict cohort in analysis.

# WARN Notice Register v1.1.1 — notice quality and provenance

This release addresses the [2026-09-24 downstream linkage audit](notice-quality-handoff-2026-09-24.md) using an isolated replay of the v1.1.0 frozen source bundle plus [dated, hash-checked official letters and California reports](../data/source_snapshots/2026-09-24-quality-evidence/manifest.json). The audit's 41 notices are a selected sample, not a population error estimate. The release retains **74,828 admitted notices, 7,815,994 reported workers, 1,009 source observations, and zero notice links**. It has **88,748 versions** because source-backed quality repairs are versioned. No notice key, effective date, listing location, worker count, or source URL changes.

## Corrections

- The Wisconsin Volta listing's San Francisco value is retained as an employer mailing location. The original letter places its one remote Wisconsin worker in Lake Geneva. The three Florida Volta rows likewise retain their distinct remote-worker cities. The letters' legal name, **Volta Charging Industries, LLC**, and March 29, 2024 letter date are recorded separately from the listing name and April 1 agency receipt/notification.
- All **21 California notices in the audit sample** now have a matched EDD report address. Across the register, 4,309 California notices match an exact employer, notice day, effective day, worker count, county, and address row in a pinned agency report. The duplicate five-worker Prospect report lines remain one notice and retain both report locators. County/address conflicts and out-of-state addresses are held. The current EDD workbook labels its date **Processed Date**; it is exported as `agency_processed_date`, not an agency receipt.
- Explicit NC and MD affected-site fields supply 2,160 addresses. NC rows whose street starts with an ordinal number and rows whose full address contains a city despite a blank separate City cell are included. Thirty NC cells with concatenated or repeated addresses, foreign location text, or a foreign city remain unresolved, with their raw text and row hashes retained. Empty site fields elsewhere remain unknown, not evidence that no site exists.
- Wisconsin's `Notice Received` and Florida's current `State Notification Date` are no longer presented as legal `notice_date`. The agency dates remain typed, and stable notice keys are preserved. This changes 6,029 notice-date values to null: 3,242 WI and 2,787 FL. Florida historical rows with a distinct `NOTICE DATE` keep that date. The WI/FL freshness checks now use their typed agency clocks.
- Source-backed negative, same-day, and at-least-300-day notice-to-action intervals are flagged for review without changing source values. Four sample notices without a recovered specific source carry a dated `specific_source_not_recovered_in_audit` status; admission is unchanged.

CSV and site detail payloads expose affected site, mailing address, date roles, source URLs, document locators, and status. Site search and summaries use the affected place when established. The detail page labels the retained agency listing location separately.

## Reconciliation

Two independent source replays have identical notice, version, link, and exception fingerprints. Their 50 CSV files and 568 site JSON files are byte-identical. The compressed SQL dump restores to a database identical across all seven tables. Their 9,668 exception entries retain the v1.1.0 checksum and the same source row accounting: 1,476 agency-cache exclusions and 1,550 current-raw exclusions. SQLite integrity is `ok` with zero foreign-key violations. The only old regression-snapshot failure is the intentional WI/FL rise in null legal notice dates; the release baseline is updated with that correction. The source replay does not establish that every state has complete historical coverage, that an unrecovered original letter is invalid, or that a timing flag proves a legal violation.

Rebuild from the [frozen source bundle](../data/source_snapshots/2026-09-24-strict-ks-ky-source-bundle.tar.gz) with `python -m warnlive.migrate.offline_rebuild --source-only --quality-evidence-dir data/source_snapshots/2026-09-24-quality-evidence` and the other dated v1.1.0 arguments in the README. The [release manifest](../data/source_snapshots/2026-09-25-quality-release-manifest.json), [replay report](../data/source_snapshots/2026-09-25-quality-candidate-report.json), and [compressed exception ledger](../data/source_snapshots/2026-09-25-quality-candidate.exceptions.jsonl.gz) record input and artifact hashes, full counts, fingerprints, and held-reason accounting. The full Python suite passed (443 tests), as did site tests (3), the site build, and the updated regression baseline.

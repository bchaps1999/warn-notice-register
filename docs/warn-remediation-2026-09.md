7. Consolidate services and CLI after the corrected data contract is stable.

## Jev evaluation boundary

[TypeSafe's official documentation](https://docs.typesafe.ai/introduction) describes Jev as a typed decision model with Choice, Score, and Noul questions. A reasonable shadow test here is a narrow classification such as address role, layoff type, or whether two already-extracted records merit human duplicate review. It should not parse PDF tables, invent missing dates or addresses, or directly merge notices. Type safety constrains the output shape, not the truth of the decision. Compare it with the current model and deterministic rules on held-out, state-stratified records; measure precision, coverage, calibration, cost, and the effect of abstention before enabling any automatic writes. TypeSafe described Jev as early access at its September 2026 launch, so this plan does not assume API credentials are available.
